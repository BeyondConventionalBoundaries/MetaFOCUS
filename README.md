# MetaFOCUS

**Metashape Functions for Optimising, Characterising, and Understanding Structure from Motion**

A toolbox of Python scripts for Agisoft Metashape Professional, free software under the GNU General Public License, version 3 or any later version. The toolbox provides control-measurement diagnostics, structure-from-motion (SfM) process analysis, filtering and project management, and surface-derived outputs. These outputs include image footprints and the ground sampling distance (GSD, also called ground sample distance or ground sampled distance).

## Requirements

- Agisoft Metashape Professional 2.x
- Developed for Metashape Professional 2.3.2 and tested offline with stand-ins for the Metashape and Qt interfaces
- NumPy, only for the normalised 8-bit and 16-bit depth export of Depth & Render Export (the 32-bit export works without it). The Python of Metashape does not include NumPy. Without it, the Depth maps tab of Depth & Render Export gives the command that installs it into the Python of your Metashape installation, when it finds that Python. Otherwise it names the article “How to install external Python module to Metashape Professional package” of the Agisoft knowledge base. Restart Metashape afterwards.
  - **Windows**, in a Command Prompt opened as administrator: `"%programfiles%\Agisoft\Metashape Pro\python\python.exe" -m pip install numpy`
  - **Windows**, in Windows PowerShell opened as administrator: `& "$env:ProgramFiles\Agisoft\Metashape Pro\python\python.exe" -m pip install numpy` (PowerShell needs the call operator `&` before a quoted path)
  - **macOS** and **Linux**: the command of the Depth maps tab, because its path holds the Python version of your installation. Agisoft’s article names Python 3.9, whereas Metashape 2.3.2 runs Python 3.12 on Windows.

## Installation

### Option A: Automatic (recommended)

1. Download and extract the MetaFOCUS ZIP file.
2. Open Metashape and go to **Tools > Run Script**.
3. Select `MetaFOCUS.py` from the extracted folder.
4. When it runs from outside Metashape’s scripts directory (first run or update), MetaFOCUS offers to install itself permanently.
   Click **‘Install permanently’** and it copies `MetaFOCUS.py` and the `MetaFOCUSCore/` folder to the scripts directory.
5. The MetaFOCUS menu loads at once for this session and on every later startup. No restart is needed. An update in a running Metashape reloads every module of MetaFOCUSCore, including that of the Export HTML page of the Interior Orientation Viewer.

### Option B: Manual

1. Download and extract the MetaFOCUS ZIP file.
2. Copy `MetaFOCUS.py` and the `MetaFOCUSCore/` folder to Metashape’s scripts directory:
   - **Windows:** `C:\Users\<YourUsername>\AppData\Local\Agisoft\Metashape Pro\scripts\`
   - **macOS:** `~/Library/Application Support/Agisoft/Metashape Pro/scripts/`
   - **Linux:** `~/.local/share/Agisoft/Metashape Pro/scripts/`
3. Restart Metashape. The MetaFOCUS menu appears automatically.

### Option C: Session only

1. Open Metashape and go to **Tools > Run Script**.
2. Select `MetaFOCUS.py`.
3. Click **‘Load this session only’** when prompted.
4. The MetaFOCUS menu is available until you close Metashape.

## Contents

The menu groups the fifteen tools as follows, in menu order. Below the groups, **Manual and Terminology** shows all About sections, that of the toolbox and those of the tools in menu order, and the terminology (see [Terminology](#terminology)) in one window, from the code of the installed version. In the running text of an About section, the first appearance of a term links to its entry in the terminology, and **Back** returns. Headings, links, code, and names such as those of the tools stay without links. Its **Save as PDF** button saves everything as one PDF file, each About section and the terminology starting on a new page, and **Save Terminology as PDF** saves the terminology alone. The PDF files keep the web links but not the links within the manual, which the Qt library of Metashape writes as links to a file, so that PDF readers show a security warning and the links do not work. The contents list of the PDF file of the manual gives the page of each section instead. **Changelog** and **About MetaFOCUS** follow.

The tools write their main actions, the settings of their runs, and their results to Metashape’s Console pane. The Console also records what a user changes in the view. These are the view controls and the tabs of the Interior Orientation Viewer, the tabs of the SfM Log Parser and the GSD Visualiser, and the filters and the search of the Marker Residual Inspector. The Console also records the suggested iteration, the iteration chosen, and the chunk buttons of the Gradual Selection Filter.

The four tools that write CSV files (the Tie Point Covariance Exporter, the Image Parameter Exporter, the Marker Residual Inspector, and the GSD Value Exporter) offer the same choice of delimiter and decimal separator. The choice is a comma with a decimal point (1.25), a semicolon with a decimal comma (1,25), for Excel with regional settings that use the decimal comma, or a tab with a decimal point. Only the numbers of the data rows take the decimal comma: the header row, the comment lines, and the text cells keep their text.

The shared module `photogrammetryUtilities.py` provides vector mathematics, ray tracing through a bounding volume hierarchy (BVH), plane fitting, N-ring vertex-normal averaging, raster DEM intersection, GSD computation, the observation and unknown counts of the bundle adjustment, and Reference panel data extraction. It has no menu entry of its own.

## GSD surface modes

The plane, triangular mesh, and raster DEM surface intersection modes are shared by the Image Footprint Generator, the GSD Value Exporter, and the GSD statistics of the Image Parameter Exporter:

- **Plane:** Fast, works immediately after orientation. The least-squares plane through the image’s 3D tie points is its own tangent plane, so the rays meet it exactly. The GSD is, as in the other modes, the side of the square with the area that the central differences span. For an image that keeps the sampling of the sensor, this area equals the GIFOV area to first order. Tie points that do not define a plane (collinear or coincident) give no plane, and the image is skipped with that reason.
- **Triangular mesh:** Accurate, follows the actual 3D surface. The tangent plane uses 3-ring averaged vertex normals, interpolated at each hit.
- **Raster DEM:** Smooth, and no BVH is needed. In a georeferenced chunk, rays meet the raster DEM in a local east-north-up CRS in metres with its origin at the perspective centre, and otherwise in the world coordinates of the chunk. Each ray (upward and horizontal rays included) is followed in steps of at most one raster DEM cell, measured horizontally. Within the first step that ends below the raster DEM surface the crossing is located by repeated linear interpolation until the heights of ray and raster DEM agree to within one hundredth of the cell size. A crossing over which the ray stays below the surface for at least one cell horizontally is therefore never passed, but a crest that the ray only clips can be. A hit beyond cells without data is the first crossing found on the raster DEM data. The Console counts the missed rays by reason. The raster DEM is read through its own projection with `Elevation.altitude()`. Metashape has no slope or aspect accessor, so the normal is taken from the raster DEM gradient. The run time grows with the length of ray that lies within the height range of the raster DEM.

The GSD is the photosite pitch projected onto the surface, for an image in which one pixel position corresponds to one photosite (not binned, downsampled, or otherwise resampled). The photosite pitch and the GSD are both often, and ambiguously, called ‘pixel size’. Strictly speaking, however, a pixel is an element of the image, not of the sensor, and has no size (Verhoeven, 2018a, 2018b). Metashape’s pixel size of the interior orientation group is the photosite pitch for an image that keeps the sampling of the sensor. In every mode, four auxiliary rays at ±½ px along the row and the column meet the tangent plane at the central ray’s hit. These rays pass through the midpoints of the edges of the photosite that corresponds to each sampled pixel position for an image that keeps the sampling of the sensor. The vectors between opposite hits are the projected row and column steps, whose lengths are the row and column sampling distances GSD_row and GSD_column. The GSD of MetaFOCUS is the area-equivalent GSD, the side of the square with the area that these steps span, √(GSD_row · GSD_column · sin φ), with φ the angle between them. To first order, this area is that onto which one sampling interval along the row and one along the column project on the tangent plane, whatever its shape. For an image that keeps the sampling of the sensor, this area is, to first order, the area of the GIFOV, the projection of one photosite. The area-equivalent GSD equals the geometric mean of GSD_row and GSD_column when the steps are perpendicular. Unlike the geometric mean, it depends only on the area that the two steps span, not on their directions. To first order, the value of a surface point therefore does not change when the camera is rolled about its camera axis, provided that the camera model, apart from its affinity and non-orthogonality, is symmetric about that axis. The camera model of a frame or fisheye camera is symmetric in this sense with the decentring distortion coefficients set to zero, without additional corrections, and without rolling-shutter compensation. Rays beyond about 84 degrees incidence are rejected, and the sampling grid is centred in the image.

For an image without rolling-shutter compensation, the rays start at the perspective centre of the image. For an image whose interior orientation group has rolling-shutter compensation (Regularized or Full), Metashape also estimates the camera motion during the readout. As a result, the position of the camera, and with the Full model also its rotation, can change from one image row to the next. Each ray of such an image is the line of the points whose residual (Camera.error) is zero at its pixel position, found by Newton’s method, and its residual is checked where it meets the surface. When a ray of such an image cannot be found in this way, every ray of that image starts at the perspective centre, so that no result mixes the two kinds of rays, and the Console says why. Such a ray is followed only from its point nearest to Camera.center, so a surface nearer to the camera than the distance that the camera moved during the readout can be missed. The GSD Value Exporter, the Image Footprint Generator, and the Image Parameter Exporter name such images in the Console. The comment line Rolling shutter of the CSV files of the GSD Value Exporter and the attribute 00_RollingShutter of the footprints say whether their rays follow the camera motion.

For an image without rolling-shutter compensation, MetaFOCUS takes the ray of Camera.unproject when its projection (Camera.project) lies within 10⁻⁶ px of the pixel position. Otherwise, MetaFOCUS refines the ray by Newton’s method, as the Interior Orientation Viewer does, because Metashape’s unprojection can stop before it has converged (up to 0.041 px for a DJI M4E calibration in Metashape 2.3.2). A pixel position whose ray cannot be brought within 0.001 px has no ray. The Console, the comment line Rays of the CSV files of the GSD Value Exporter, and the attribute 00_Rays of the footprints say how many pixel positions have no ray. They also say for how many pixel positions the ray of Metashape’s unprojection projected back more than 0.001 px from the pixel position, so that MetaFOCUS refined it. A border pixel position without a ray makes a footprint partial.

## Terminology

The terminology of **MetaFOCUS > Manual and Terminology** defines the terms of the tools, their About sections, and the MetaFOCUS paper and names the literature they follow. In brief, a pixel is an element of the digital image, a dimensionless point sample with a position and a value but no size, shape, area, edges, or centre (Smith, 1995, 2021, and Verhoeven, 2018a). The sensor generates it, but it belongs to the digital image, not to the sensor, and its position lies in image space, the two-dimensional domain of positions in an image. By contrast, the photosites of the sensor lie in the optical image space, the image-side optical domain in which the optics form the image. Object space is the physical scene whose positions and geometry are described mathematically, and the 3D model is the mathematical representation, containing the model points and the modelled camera geometry. A photosite is one of the individual photon-sensing sites that make up the sensor (Verhoeven, 2018a). The photosite pitch is the distance between the centres of neighbouring photosites, which in a regular sensor is also the width of one photosite (Verhoeven, 2018b). The ground sampling distance is the distance between the surface points that the rays through two neighbouring pixel positions meet. For an image that keeps the sampling of the sensor, this distance is the photosite pitch projected onto the surface (the ground-projected sample interval of Schowengerdt, 2007). The projection of one photosite onto the surface is the ground-projected instantaneous field of view (GIFOV) of Schowengerdt (2007). MetaFOCUS means the projection of the whole photosite, not only of its light-sensitive area, and likewise for the instantaneous field of view (IFOV), the angle that one photosite subtends at the perspective centre. The GIFOV is a geometric quantity. It does not equal the surface patch whose reflected radiation contributes to one pixel value: that patch is larger and has no sharp edge. MetaFOCUS never gives a pixel a size, an area, or a place on the surface. The principal distance c is a length, given in millimetres. For an image that keeps the sampling of the sensor, c<sub>pix</sub> = c/p, with p the photosite pitch, is the principal distance in pixels, which Metashape stores as the attribute f of its calibration. A value in px is then a value in photosite pitches. MetaFOCUS writes f and f′ only for the focal length of a lens. A tie point is a point that is measured in two or more images. MetaFOCUS writes 3D tie point for the point whose 3D coordinates the bundle adjustment estimates (Metashape’s tie point). It writes 2D tie point, also image tie point, for the measured position of that point in one image (Metashape’s tie point projection), and tie point for the point as a whole. The page also defines the perspective centre, the principal distance, orientation, structure from motion, keypoints, scale bars (physical bars), reference distances, and Metashape scale bars. It defines coordinate systems, coordinate reference systems (CRSs), and datums as ISO 19111:2019 defines them, and the uncertainty terms of the VIM, the GUM, and ISO 5725-1:2023. The page gives the references of its terms (among them Fiete, 2010, Förstner and Wrobel, 2016, Granshaw, 2020, Luhmann et al., 2023, Schowengerdt, 2007, Smith, 1995, 2021, and Verhoeven, 2018a, 2018b). A concordance at the end of the page maps the names of Metashape to the terms of MetaFOCUS. For example, it maps Align Photos to running the structure-from-motion (SfM) procedure and its aligned cameras to oriented images, and Optimize Cameras to bundle adjustment. It also maps the Accuracy fields to a priori standard deviations and the criteria of Clean Tie Points to what they measure.

## Issues

Faults in the tools of MetaFOCUS and suggestions to improve their code can be reported as issues on GitHub, with the two forms of the repository. The form for a fault asks for the tool, the versions of MetaFOCUS and Metashape, the operating system, the steps, what happened, and the Console text. Issues are not for help with Metashape itself or with individual projects.
